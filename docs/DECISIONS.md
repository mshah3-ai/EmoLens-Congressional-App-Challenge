# Decisions and substitutions

| # | Spec says | What we did | Why |
|---|---|---|---|
| 1 | Engine has zero runtime dependencies | Engine imports `@emolens/shared` (our own package: types, registry, constants) | Registry must be shared by engine, app and portal; it adds no third-party code |
| 2 | Dates via `date-fns-tz` | Engine uses the built-in `Intl.DateTimeFormat` for time-zone math | Keeps the engine dependency-free; the mobile app may still use date-fns-tz for display |
| 3 | Store instants as ISO strings | Inside the engine, instants are epoch milliseconds | Faster comparisons; the app converts when building a ChildDataset |
| 4 | Engine tests with jest | Engine tests use Node's built-in `node:test` run through `tsx` | No extra dependency; mobile app tests still use jest as specified |
| 5 | Last night's sleep must come before block_start | Uses the sleep entry ending on this local date and before the block END | A child waking at 6:45 still has "last night" for the 6-8 am block |
| 6 | `hunger_gap` definition | Set to 0 when `meal_missing` = 1 | Same "missing -> 0 plus indicator" pattern the spec uses for sleep, noise and physiology |
| 7 | `p = sigma(mu / sqrt(1 + pi v / 8))` | Clamped into [p_lo, p_hi] | Only matters for extreme mu*sqrt(v) (> ~6); guarantees the displayed range contains the displayed probability |
| 8 | "About N x usual" vs a time-of-day baseline | Uses the baseline model's prediction for the same block | The baseline model is exactly the time-of-day model the spec compares against |
| 9 | Newton backtracking tolerance 1e-12 | Relative tolerance 1e-12 * max(1, abs(L)) | The absolute test stalled short of the optimum due to floating-point noise |
| 10 | Spec names no linter | ESLint 10 flat config (`eslint.config.mjs`) with `typescript-eslint` recommended rules, plus `tsc --noUnusedLocals --noUnusedParameters`, as each package's `lint` script | Standard TypeScript tooling; enforces the spec's no-`any` rule automatically. `eqeqeq` allows `x != null` (null-or-undefined check) |
| 11 | CI runs the simulator smoke test | Until Phase 2 adds `packages/simulator/src/run.ts`, the CI step is skipped (`if: hashFiles(...)`) | The simulator has no entry point yet; the step turns on automatically once it exists |
| 12 | Hysteresis: "2 consecutive daily fits" (14.3) | `StatusHistoryEntry` stores `lastRawDate`; several fits on the same local date count as one | The app refits after every label change, so counting fits would let a status drop after two fits a minute apart |
| 13 | Status thresholds written inline in 14.3 | Same numbers, moved to `STATUS_THRESHOLDS` in `packages/shared/src/constants.ts` | Makes the tunable thresholds (26.6) one documented constant |
| 14 | `TAU_GRID = [0.5, 0.75, 1.0, 1.5]` | `[0.75, 1.0, 1.5]` | Allowed tuning (26.6). With tau = 0.5 the narrowed-but-not-moved positive prior means alone pushed null triggers to "likely". Effect in `docs/VALIDATION.md` tuning log |
| 15 | Scenario JSON (26.1) has no start date or time zone | Optional `startDate` (default 2026-09-07, a Monday) and `timeZone` (default America/New_York) | Needed to build local blocks; the 120-day run then crosses the 2026-11-01 DST change |
| 16 | 26.2 simulated caregiver: end-of-day check only | Also simulates the next-morning follow-up (spec 16) for blocks ending after the 20:30 check, with the same `eodCompletion` probability | Without it the 20-22 block could only ever be labeled positive, creating a fake evening effect |
| 17 | 26.3 "forecast quality ... next 7 days" | For day d: day-ahead predictions (each made at 18:00 the evening before) for days d+1..d+7, scored against true outcomes (logged or not), intervened blocks excluded. Also reported: expected skill (Brier against the true chance) and an oracle ceiling | The spec does not define the window precisely; the extra metrics separate model quality from coin-flip noise |
| 18 | 26.2 generator details not specified | Pressure mean reversion 0.02/h; temperature seasonal + diurnal + AR(1) noise; AQI spike days 3%; sound as 15-minute stretches (home room sensor 24 h with temperature, phone elsewhere); parent's episodes-per-week guess = truth x U(0.7, 1.3); episodes logged immediately; a "happened" answer always leaves a fast-path episode (15.4). | 19 | E6 "with vs without physiology" | Both arms use the same simulated children with a true `hr_elevated_pre` effect of 0.5; one arm's app sees heart-rate data, the other's does not | Answers "does using physiology help?" with everything else identical |
| 20 | E3 "weak prior (all trigger sds = 5)" | Trigger prior sd 5 with tau fixed at 1 | Otherwise tau selection would rescale the weak prior |
| 21 | Figures with Python 3.11+ | Python 3.12 from Homebrew in a local `.venv` (gitignored) | Matches the spec |
| 22 | pnpm workspaces (SPEC 4) | `.npmrc` sets `node-linker=hoisted` | Expo supports isolated installs from SDK 54, but its monorepo guide says some native libraries still break; hoisted is the documented safe option for EAS cloud builds that we cannot debug locally |
| 23 | op-sqlite with SQLCipher (3.1) | `"op-sqlite": {"sqlcipher": true}` is in BOTH `apps/mobile/package.json` and the root `package.json` | With a hoisted install, op-sqlite's iOS podspec searches upward from `node_modules` and finds the root `package.json`, while its Android Gradle script reads the app's.
